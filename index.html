Weather
Application
Role Solo Developer
Stack JavaScript · OpenWeather API · CSS3
Type Frontend Project
View on GitHub
Overview

A real-time weather forecasting web application that integrates with the OpenWeather API to deliver accurate, live weather data for any city worldwide. Designed with a mobile-first approach and polished UI interactions.

The project was built to practice asynchronous JavaScript, REST API consumption, and dynamic DOM manipulation — core skills for any frontend or full-stack developer.

Problem Statement

Weather apps are everywhere — but most existing ones are either bloated with features or poorly implemented for learning purposes. The goal was to build a production-quality weather dashboard that demonstrates real async handling, error states, and responsive design — not just a tutorial clone.

Key Features
  • Real-time weather data via OpenWeather API with live fetch on every search
  • 5-day forecast view with daily temperature highs and lows
  • Dynamic weather icons that change based on conditions
  • Graceful error handling for invalid cities and network failures
  • Fully responsive layout from mobile to desktop
  • Search history stored in localStorage for quick access
Technical Challenges

Async API handling — Managing multiple simultaneous fetch calls (current weather + forecast + geolocation) without UI jank required careful Promise chaining and loading state management.

Dynamic rendering — Building a UI that cleanly re-renders for each new search without page reload, while also managing skeleton loading states, required disciplined DOM diffing in vanilla JS.

Lessons Learned

Working with external APIs taught me how to handle rate limits, CORS, and API key security. The project solidified my understanding of async/await patterns, error boundaries, and progressive enhancement — skills I now apply across all my projects.

Origin Thinkathon 2026 → Ongoing

Overview

CropCare is an AI crop health and disease management platform built with React, TypeScript, Supabase, and Tailwind CSS. It helps farmers identify plant diseases, monitor soil health, and manage treatments — with a multilingual AI agronomy assistant supporting English, Hindi, and Punjabi for real accessibility in the field.

Evolved from the AgriDetect hackathon prototype into a full product — the strongest technical project in the portfolio, combining AI API integration, full-stack architecture, and real-world domain impact.

Key Features
  • Leaf disease detection with AI-powered identification of crop diseases
  • Soil health module tracking soil conditions and providing recommendations
  • Visual disease reference database for quick offline lookup
  • Treatment tracking with scheduled reminders for medication and care
  • Multilingual AI agronomy assistant — responds in English, Hindi, and Punjabi
  • Seasonal recommendations tailored to crop and region
  • Interactive quizzes for farmer education on crop disease management
Technical Challenges

Offline-first in rural conditions — AI API calls fail without internet. Built a comprehensive local disease database as graceful fallback, with sync-on-reconnect logic.

Scaling from hackathon MVP to real product — v1 was a 24-hour build. Refactoring into a maintainable full-stack architecture (auth, persistent data, multi-user) required rethinking the entire data model.

Positioning

CropCare demonstrates AI integration, full-stack architecture, offline resilience, and real-world problem solving — exactly the combination that strong internship candidates show. Agriculture + AI is a high-growth domain with genuine differentiation from generic CRUD projects.

Overview

SmartHire AI is an AI-powered career platform that helps job seekers build better resumes, understand ATS systems, and optimize for specific job descriptions — built as a genuine tool, not just a portfolio piece.

Addresses a real pain point: most students have no idea why their resumes get rejected. SmartHire surfaces the exact reasons with actionable fixes.

Key Features
  • AI resume analyser evaluating ATS compatibility, structure, readability, grammar, and measurable achievements
  • Actionable improvement recommendations surfaced per section
  • Job-description keyword matching — classifies skills as matched, partially matched, or missing
  • Interactive analytics dashboard showing resume health at a glance
Technical Challenges

ATS simulation accuracy — Real ATS systems are proprietary black boxes. Building a scoring model that meaningfully predicts ATS behaviour required studying public ATS documentation and testing against known pass/fail outcomes.

Keyword classification — Distinguishing "matched", "partially matched", and "missing" skills required semantic similarity logic rather than simple string matching, since job descriptions rarely use the exact same phrasing as resumes.

🎤 LiveMirror
Status In Development
Stack React · TypeScript · Gemini API · Node.js · PostgreSQL
View on GitHub
Overview

LiveMirror is an AI interview simulation platform — currently in development — that generates role-specific interview questions, gives personalised feedback on responses, and runs voice-based mock interviews with speech analysis and structured AI-driven performance evaluation.

Built with React, TypeScript, Tailwind CSS, Gemini API, Node.js, Express.js, and PostgreSQL.

Key Features
  • Role-specific interview question generation via Gemini API
  • Voice-based mock interviews with real-time speech input
  • Speech analysis — pacing, filler words, response clarity
  • Structured AI-driven performance evaluation per answer
  • Personalised feedback with improvement areas highlighted
  • Session history stored in PostgreSQL for progress tracking
Technical Challenges

Streaming AI responses during live interviews — Waiting for a full Gemini API response between question and feedback breaks the interview flow. Implementing streamed responses lets feedback begin rendering while the model is still generating.

Speech-to-text reliability — Browser Web Speech API accuracy varies by accent and environment. Building a fallback that gracefully handles low-confidence transcriptions without stalling the session required careful error state design.

💰 FinPilot AI
Status In Development
Stack React · TypeScript · Supabase · PostgreSQL
View on GitHub
Overview

FinPilot AI is a personal finance management platform built to give users clarity over their money — tracking transactions, budgeting against categories, setting savings goals, and monitoring debt repayment, all in one interactive dashboard.

Built with a React + TypeScript frontend, Supabase backend, and PostgreSQL for structured financial data with row-level security. The interactive dashboard uses spending analytics and goal-progress visualisation to make financial data actionable rather than just informational.

Key Features
  • Transaction tracking with date, category, merchant, and amount
  • Budget management — set monthly limits per category and track remaining budget in real time
  • Savings goals with contribution tracking and progress visualisation
  • Debt tracking — balances, interest rates, and repayment progress
  • Interactive analytics dashboard with spending breakdowns and trend charts
  • Goal-progress visualisation showing distance to each savings target
Technical Challenges

Financial data security — Personal finance data is sensitive. Supabase row-level security policies ensure each user's transactions, budgets, and goals are completely isolated — no user can read another's data, even with a valid JWT.

Real-time budget updates — As transactions are added, budget remaining values and goal progress need to update instantly without a page reload. Supabase real-time subscriptions handle this cleanly without manual polling.

Frontend · SPA · Design System
Portfolio
Website
Stack HTML5 · CSS3 · Vanilla JS
Type Single-File SPA
View Source
Overview

This portfolio was designed and built from scratch — no templates, no frameworks, no UI libraries. A complete single-file SPA with a custom page router, scroll animations, custom cursor, and 7 distinct pages.

Every design decision was intentional: the Syne display font for authority, JetBrains Mono for developer credibility, the acid yellow accent for memorability, and the editorial brutalist layout to stand out from generic student portfolios.

Architecture Decisions
  • Single-file SPA with a custom JS router — no build tool needed, zero dependencies
  • CSS custom properties for a consistent design system across all pages
  • IntersectionObserver for scroll-triggered animations — no library needed
  • CSS Grid and Flexbox for the layout system — no Bootstrap
  • Lazy reveal animations using CSS transitions + JS class toggling
Design System

Font: Syne + DM Sans + JetBrains Mono
Accent: #e8ff47 (acid yellow)
Background: #0a0a0a
Aesthetic: Editorial Brutalism
